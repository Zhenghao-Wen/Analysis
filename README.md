### 安装包来源校验（「我已知晓」→ 验证提交哈希）

> **引入提交：[`19db770`](https://github.com/Zhenghao-Wen/Analysis/commit/19db7707ab226af28ed186761d8caba582782695)**
> （`feat(ui): 强化安装包来源校验——「我已知晓」后必须输入 7 位提交哈希`）

自该提交起，上面的提示不能再一键跳过，弹窗流程改为两步：

1. 提示弹窗的主按钮为 **「我已知晓」**，点击后不会进入应用，而是弹出第二步；
2. 第二步要求输入 **本安装包对应源码提交的 7 位哈希**，与打包时写入产物的提交哈希一致，
   才能进入应用；输入不一致会提示「哈希不匹配」并停留在校验框。

同时移除了旧版的「此版本不再提示」按钮 —— 它会绕过校验，使防伪失去意义。
两步弹窗均**不可点击空白关闭**。

#### 校验值从哪来

打包时由 Gradle 执行 `git rev-parse --short=7 HEAD` 并把结果写进构建产物
（`shared` 的 `ASBuildConfig.GIT_COMMIT_HASH`、`app` 的 `BuildConfig.GIT_COMMIT_HASH`）。
因此：

- **拉取源码本地编译**：写入的是你本地工作树的 HEAD 提交，可用
  `git rev-parse --short=7 HEAD` 直接查到；
- **CI 构建**：写入的是 CI checkout 到的提交，可在构建日志或仓库提交记录中查到。

两者都指向真实的源码仓库与提交，所以任何一个安装包都能追溯到它对应的源码版本。
只取前七位是为了让人可以直接在仓库的提交列表里肉眼比对。

#### 何时要求校验

首次安装使用，以及**升级到新版本后首次使用**时都会要求校验：
是否已校验是按「版本号 + 提交哈希」记录的，版本或提交变化后会重新要求。
校验通过后该记录写入 DataStore，同一构建不再重复打扰。

> 补充：若构建产物中**没有**提交信息（例如用源码压缩包编译、`.git` 目录缺失，
> 导致哈希为空），校验框会明确提示「未包含构建期提交信息，无法完成校验」并直接放行，
> 避免把正常用户锁在门外。

#### 如何据此识别伪造包

- 安装后**完全没有**出现「我已知晓」→「验证」流程；
- 或校验框输入与你所拿到源码提交**明显一致**的哈希却始终提示不匹配；

出现以上情况，说明安装包并非由对应源码正常打包，应立即停止使用。
